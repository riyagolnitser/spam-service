# Spam Classification API

ML-микросервис для бинарной классификации электронных писем: `spam` / `ham`.

Модель упакована в Docker-контейнер и опубликована на Render. Работоспособность публичного API проверена запросами к `/health` и `/predict`.

## Публичный сервис

- Главная страница: https://spam-classification-api-2zf0.onrender.com
- Swagger UI: https://spam-classification-api-2zf0.onrender.com/docs
- Проверка состояния: https://spam-classification-api-2zf0.onrender.com/health
- OpenAPI: https://spam-classification-api-2zf0.onrender.com/openapi.json

Репозиторий: https://github.com/riyagolnitser/spam-service

Репозиторий закрытый. Для просмотра исходного кода необходимо предоставить доступ проверяющему.

## Цель проекта

Определять спам по тексту электронного письма с приоритетом на минимизацию ложноположительных срабатываний — случаев, когда легитимное письмо ошибочно классифицируется как спам.

Порог классификации подбирается на валидационной выборке: максимизируется Precision(spam) при условии Recall(spam) ≥ 0.90.

### Подготовка данных

- Парсинг писем и извлечение темы и тела.
- Объединение темы и тела в текстовую строку.
- Удаление HTML-тегов, скриптов и стилей.
- Нормализация пробелов и приведение к нижнему регистру.
- Удаление дубликатов по нормализованному тексту.
- Стратифицированное разделение с `random_state=42`.

|---|---:|
| Train | 4 785 |
| Validation | 1 026 |
| Test | 1 026 |

Исходные данные и подготовленные CSV не включены в репозиторий. Для повторного обучения необходимо отдельно разместить исходные данные в ожидаемых папках.

## Модель

Архитектура:

Текст → TF-IDF + дополнительные числовые признаки → Logistic Regression → вероятность спама → сравнение с порогом.

Параметры:

- TF-IDF: слова и биграммы.
- Максимальное количество текстовых признаков: 50 000.
- `min_df=2`, `sublinear_tf=True`.
- Logistic Regression с `class_weight="balanced"`.
- Проверенные значения `C`: 0.1, 1.0, 3.0, 10.0.
- Выбранное значение `C`: 10.0.
- Порог классификации: приблизительно 0.7959. Точное значение хранится в артефакте модели и `metrics.json`.

Для каждой конфигурации порог подбирался на validation с ограничением Recall(spam) ≥ 0.90. Среди проверенных конфигураций выбрана модель с максимальным F1(spam) на validation.

Векторизатор и классификатор обучались на train. Тестовая выборка не использовалась для выбора параметра `C` и порога.

## Результаты

| Выборка | Precision(spam) | Recall(spam) | F1(spam) | Accuracy |
|---|---:|---:|---:|---:|
| Validation | 0.9802 | 0.9182 | 0.9482 | 0.9737 |
| Test | 1.0000 | 0.9294 | 0.9634 | 0.9815 |

Матрица ошибок на test:

| Фактический класс | Предсказан ham | Предсказан spam |
|---|---:|---:|
| Ham | 757 | 0 |
| Spam | 19 | 250 |

На данном тестовом наборе ложноположительных срабатываний не зафиксировано. Из 269 спам-писем обнаружено 250, пропущено 19.

Результаты относятся к внутреннему тестовому разбиению и не гарантируют аналогичное качество на новых источниках данных.

## API

### GET /health

Проверка состояния сервиса.

Пример ответа:

```json
{
  "status": "ok",
  "model_loaded": true
}
```

### POST /predict

Вход:

```json
{
  "text": "Congratulations! You have won a free iPhone. Click now to claim your prize!"
}
```

Пример фактического ответа опубликованного сервиса:

```json
{
  "label": "spam",
  "label_id": 1,
  "confidence": 0.999879758628561,
  "spam_probability": 0.999879758628561,
  "needs_human_review": false
}
```

Поля ответа:

- `label`: `spam` или `ham`.
- `label_id`: 1 для spam, 0 для ham.
- `spam_probability`: оценка вероятности спама, возвращаемая моделью.
- `confidence`: значение `spam_probability` для spam или `1 - spam_probability` для ham. Это расчётный показатель, а не гарантия правильности.
- `needs_human_review`: `true`, если `spam_probability` находится в диапазоне от 0.40 до 0.60 включительно.

Флаг ручной проверки не отменяет бинарный ответ: поле `label` возвращается в любом случае.

## Пример запроса из PowerShell

```powershell
$body = @{
    text = "Congratulations! You have won a free iPhone. Click now to claim your prize!"
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri "https://spam-classification-api-2zf0.onrender.com/predict" `
    -Method Post `
    -Body $body `
    -ContentType "application/json"
```

## Локальный запуск

Требуется Python 3.12 и файл `spam_model.joblib` в корне проекта.

Из корня проекта:

```powershell
python -m pip install -r requirements.txt
python -m uvicorn service.app.main:app --reload --port 8000
```

Swagger UI:

```text
http://127.0.0.1:8000/docs
```

## Запуск через Docker

Требуется установленный и запущенный Docker.

```powershell
docker build -t spam-service .
docker run --rm -p 8000:8000 --name spam-api spam-service
```

Если порт 8000 уже занят локальным Uvicorn, сначала остановите его либо используйте:

```powershell
docker run --rm -p 8001:8000 --name spam-api spam-service
```

Во втором случае Swagger доступен по адресу:

```text
http://127.0.0.1:8001/docs
```

Docker-образ успешно собран и запущен на Render. Локальная сборка Docker на ноутбуке не выполнялась.

## Ограничения и дальнейшие улучшения

- Основные данные — англоязычные письма; качество на русском языке не оценивалось.
- Отдельный внешний тестовый набор не использовался.
- Категоризация писем по темам не реализована.
- Предобработка обучения и API пока не вынесена в общий модуль и различается: подготовка данных включает очистку HTML и приведение текста к нижнему регистру.
- Часть дополнительных признаков требует пересмотра: очистка данных удаляет HTML и регистр, а нормализация пробелов убирает разделитель темы и тела.
- Текущая кросс-валидация использует заранее рассчитанные TF-IDF-признаки и подбор порога на оцениваемом фолде; её результаты следует считать предварительными.
- Планируется единый пайплайн предобработки, корректная кросс-валидация с обучением векторизатора внутри фолдов, внешний тест и сравнение альтернативных моделей.
